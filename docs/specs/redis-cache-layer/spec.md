# Redis 缓存层（Cache-Aside + 穿透/击穿/雪崩三件套）Spec

## 背景

- 视频详情与推荐列表是「读多写少」的高频路径，当前直接查 PostgreSQL，高并发下 DB 是瓶颈。
- `GetVideoInfo` 已有一份手写 cache-aside（Redis GET → `SetNX` 锁 5s → 查库 → 随机 TTL 回写），但逻辑散落在 handler 中：锁可能泄漏、无空值/穿透处理、无法复用。
- `GetVideoRecommend`（公开推荐列表）完全直查 DB，每次还批量 RPC 查询作者信息，是当前最痛的热点。
- 已有可复用基础：`core.Redis`（go-redis v9）、`timeutil.RandomRangeExpire`（随机 TTL）、`golang.org/x/sync`（singleflight）。无布隆过滤器库。

## 目标

- 把缓存读写封装成**通用组件**，供详情、列表及后续其他读路径复用。
- 落实缓存三件套：**穿透**（空值缓存 + 布隆过滤器）、**击穿**（singleflight + Redis 互斥锁）、**雪崩**（随机 TTL）。
- 接入两个读路径：**视频详情**、**推荐列表**；并保证写路径（更新/删除）正确失效缓存。

## 功能需求

- **F1（通用缓存组件）**：提供一个可复用的 Cache-Aside 读接口，内部自动完成「读缓存 → 未命中则回源 → 写缓存」全流程，并对调用方隐藏穿透/击穿/雪崩处理细节。

- **F2（击穿防护）**：热点 key 过期瞬间大量并发请求时，仅允许一个请求回源 DB：
  - 进程内用 singleflight 合并同一 key 的并发回源；
  - 跨实例用 Redis `SetNX` 互斥锁（带过期时间、锁释放须校验持有者，避免误删他人锁）；
  - 未抢到锁的请求等待后重新读缓存，仍失败则返回降级结果（直查 DB 兜底）。

- **F3（穿透防护）**：
  - **空值缓存**：查询不存在的 ID 时，将「空结果」以短 TTL 缓存，避免每次穿透到 DB；
  - **布隆过滤器**：用 Redis bitmap 自实现（不引入第三方库），在查询前拦截「一定不存在」的 ID；过滤器需支持从现有视频 ID 集合（重新）构建。

- **F4（雪崩防护）**：缓存过期时间使用随机 TTL（复用 `timeutil.RandomRangeExpire`），避免大量 key 同时过期打崩 DB。

- **F5（接入视频详情）**：改造 `GetVideoInfo` 使用通用组件，行为与现有响应结构保持一致（含封面 URL、作者信息）。

- **F6（接入推荐列表）**：改造 `GetVideoRecommend` 使用通用组件缓存推荐结果（含作者信息），用短 TTL 控制时效性。

- **F7（写路径失效）**：更新视频信息（`PutVideoInfo`）、删除视频（`DeleteVideo`）后，失效对应的详情缓存与推荐列表缓存，使下次读取拿到最新数据。

## 非功能需求

- **N1**：不改变现有 HTTP API 契约与响应 JSON 结构（前端无感知）。
- **N2**：缓存层为旁路（Cache-Aside），Redis 不可用时自动降级为直查 DB，不影响可用性。
- **N3**：通用组件无业务耦合，后续可复用于点赞计数、播放量等读路径。
- **N4**：不新增第三方缓存库；singleflight 使用已在依赖中的 `golang.org/x/sync`，布隆过滤器基于 Redis bitmap 自实现。
- **N5**：日志可观测——回源、命中、击穿触发、布隆过滤命中应有结构化日志。

## 不做的事

- 不做用户自己的视频列表（`GetSelfVideoPage`）缓存（per-user、收益低）。
- 不重构 STS 凭证缓存（已有实现，不在本次范围）。
- 不做缓存与 DB 的强一致性（延迟双删等）；本次采用「更新后删除缓存」的最终一致策略。
- 不引入独立缓存框架（如 go-redis/cache、gocache）。
- 不触碰 HTTP/CDN 层缓存（`GetVideoMdp` 的 `Cache-Control` 保持现状）。
- 不实现布隆过滤器的「删除元素」能力（由定期重建兜底）。

## 验收标准

- **AC1（F1）**：存在一个通用缓存组件，且被详情、列表两个读路径调用（验证：编译通过 + 代码审查确认无散落的手写缓存逻辑）。
- **AC2（F2）**：并发请求同一个已过期 key 时，单实例内 DB 回源次数为 1；多实例下通过 `SetNX` 互斥，未抢到锁的实例不会重复回源（验证：压测 + 回源日志计数）。
- **AC3（F3）**：查询不存在的 ID，首次回源后写入空值缓存，后续请求命中空值缓存不再打 DB；布隆过滤器能拦截「一定不存在」的 ID（验证：构造不存在 ID 连续请求，观察 DB 查询日志）。
- **AC4（F4）**：不同 key 写入的缓存 TTL 为随机值而非固定值（验证：`TTL` 命令观察多个 key）。
- **AC5（F5/F6）**：详情、推荐列表的响应 JSON 结构与改造前一致（验证：接口返回 diff 无差异）。
- **AC6（F7）**：更新或删除视频后，对应详情缓存与推荐列表缓存被删除，下一次请求返回最新数据（验证：改标题后立即请求，返回新标题）。
