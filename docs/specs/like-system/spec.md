# 高并发点赞/收藏/播放量计数 + 热门榜单 Spec

## 背景

- 项目已有 `video_likes` / `video_favorites` / `video_play_logs` 三张表（AutoMigrate），但**无任何点赞/收藏/播放量的 API**。
- `videos` 表无计数冗余列，展示计数需实时聚合（高并发下不可行）。
- 已有可复用基础：`core.Redis`、Cache 层（读缓存）、限流中间件（登录接口保护）、Kafka（转码/删除）。
- 目标：实现高并发下的「点赞系统」闭环——Redis 计数 + 去重 + 异步落库 + 榜单。

## 目标

- **点赞/收藏**：用户维度去重、可取消（toggle），高并发读写走 Redis。
- **播放量**：每次播放 +1（计数维度，不去重）。
- **异步批量落库**：DB 不承受实时写入压力。
- **热门榜单**：Redis ZSet 按计数排序。

## 功能需求

- **F1（点赞 toggle）**：认证用户对视频点赞/取消点赞（`POST /videos/:id/like`）；同一用户对同一视频最多计 1 次；重复操作幂等，返回最新状态与计数。

- **F2（收藏 toggle）**：认证用户对视频收藏/取消收藏（`POST /videos/:id/favorite`），语义同点赞。

- **F3（播放量上报）**：每次播放调用上报接口（`POST /videos/:id/play`），计数 +1，不去重。

- **F4（实时计数）**：点赞/收藏用 Redis Set 去重（`SADD`/`SREM`，计数用 `SCARD`，状态用 `SISMEMBER`）；播放量用 `INCR`。三计数可实时读取。

- **F5（计数与状态查询）**：提供视频三计数（点赞/收藏/播放）与「当前用户是否已赞/已收藏」的查询。

- **F6（异步批量落库）**：点赞/收藏/播放事件写入 Redis 待处理队列；后台定时批量 drain 并写 DB——更新 `videos` 冗余计数列（`like_count`/`favorite_count`/`play_count`）+ 写/删明细表（`video_likes`/`video_favorites`/`video_play_logs`）。落库重试幂等。

- **F7（热门榜单）**：Redis ZSet 维护视频按计数（播放量/点赞数）排序，提供 Top N 榜单查询。

- **F8（降级）**：Redis 不可用时，计数查询回退读 DB 冗余列（不 5xx）；写入操作返回明确错误（不静默丢计数）。

## 非功能需求

- **N1**：高并发读写走 Redis，DB 仅承受批量落库压力。
- **N2**：计数最终一致（Redis 实时、DB 秒级追上）；落库重试幂等不重复。
- **N3**：不破坏既有 API 契约；新增接口与字段向后兼容。
- **N4**：结构化日志与可观测（计数写入、落库批次、榜单更新）。
- **N5**：无第三方依赖（复用现有 go-redis / GORM / snowflake / gin）。

## 不做的事

- 不做评论功能（表已有，API 留待后续）。
- 不做推荐算法（榜单仅按计数简单排序）。
- 不做播放量去重（明确每次播放 +1；匿名刷量防护属后续 IP 限流范畴）。
- 不做跨视频实时统计面板 / 复杂聚合。

## 验收标准

- **AC1（F1/F2）**：同一用户重复点赞只计 1，再点取消计数归 0；状态正确反映。
- **AC2（F3）**：调用播放上报 N 次，播放量 +N。
- **AC3（F4）**：计数可实时从 Redis 读到，且与操作一致。
- **AC4（F5）**：查询接口返回三计数 + 当前用户状态。
- **AC5（F6）**：异步落库后 DB 冗余列与明细表与 Redis 计数最终一致；重试不重复。
- **AC6（F7）**：榜单按计数降序返回 Top N。
- **AC7（F8）**：Redis 关闭时计数查询回退 DB（不 500）。
