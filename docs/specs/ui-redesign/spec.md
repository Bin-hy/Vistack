# UI 次世代重构（深色玻璃拟态）Spec

## 背景

当前前端（`web-client` 用户端 + `web-admin` 管理端）采用 B 站风浅色主题，仅浅色模式，设计 token 简陋；交互层面存在以下「不严谨」问题：

- 使用原生 `alert()` / `confirm()` 弹窗（投稿、删除等场景）。
- 导航栏链接为死链（动画/游戏/影视/直播全部指向 `/`），搜索无结果页。
- 图标用 emoji（🔔📜⭐🕘）与 PNG 图片混用，风格不统一。
- 大量硬编码颜色类名混杂（`blue-*` / `pink-*` / `gray-*` 与 token 混用）。
- 加载态/空态/错误态粗糙或缺失；播放页「相关推荐」为假数据占位。
- `web-admin/src/style.css` 残留 Vite 脚手架样式（`h1 3.2em`、全局 `button`、`#app` 限宽居中），破坏布局。
- 两端各自维护一套 `components/ui`，组件风格不一致。

目标是把两端统一为「**深色沉浸 + 玻璃拟态 + 蓝紫渐变（indigo→violet）**」的次世代视觉，并系统性提升交互严谨度，同时保持现有功能与后端 API 契约不变。

## 目标

- 统一 web-client 与 web-admin 为深色玻璃拟态设计语言，蓝紫渐变强调色。
- 建立单一设计 token 来源（颜色/圆角/阴影/玻璃/动效），消除硬编码颜色与蓝/粉混用。
- 提升交互严谨度：移除原生弹窗、修复死链、统一图标、完善加载/空态/错误态。
- 纯前端视觉与交互改造，不改后端、不改路由与 API 契约、不改 Pinia 状态逻辑。

## 功能需求

- **F1（设计 token）**：在两端 `style.css` 定义统一的深色设计 token——深色背景/前景、玻璃卡片（半透明 + backdrop-blur）、蓝紫渐变主色、边框、圆角、阴影、动效时长，作为唯一样式来源；两端 token 值完全一致。
- **F2（全局主题）**：根元素为深色背景 + 低对比渐变光晕（indigo/violet 柔光），正文前景高对比；全局 `color-scheme: dark`，滚动条/表单控件深色化。
- **F3（布局导航）**：两端 `BiliLayout` 导航栏玻璃化（毛玻璃 + 半透明 + 顶部吸顶），Logo/标题、真实路由链接、搜索框、头像菜单统一；移除死链与 emoji 图标，改为统一图标组件。
- **F4（首页）**：web-client 首页「热门推荐」改为玻璃卡片视频流，封面加载占位 + 骨架屏加载态 + 空态；卡片 hover 有抬升/光晕动效。
- **F5（播放页）**：播放器外壳与信息区玻璃化；点赞/收藏/转发改为统一图标按钮并带点击反馈（选中态/计数占位）；UP 主信息卡与「相关推荐」占位优化（保持占位但视觉精致）。
- **F6（创作者中心）**：投稿表单、上传进度条、封面裁剪、视频管理列表、编辑/删除对话框全部玻璃化与组件化；移除原生 `alert`/`confirm`，改用自定义 Toast 与确认对话框；清理内联颜色。
- **F7（登录/注册/个人中心）**：AuthLogin、AuthRegister、Profile 统一深色玻璃视觉，表单聚焦/错误态明确。
- **F8（管理端）**：web-admin 使用与 web-client 相同的 token 与组件风格；清理 Vite 脚手架残留样式；登录/注册/首页玻璃化。
- **F9（组件收敛）**：两端 `components/ui`（button/card/input 等）统一为同一套风格与 token 引用；引入统一图标方案（如 lucide-vue-next），替换 emoji/PNG/内联 SVG。

## 非功能需求

- **N1（一致性）**：两端共用同一套 token 值，视觉无差异，无硬编码颜色。
- **N2（响应式）**：桌面与移动端均保持玻璃拟态与可用性，导航/列表在窄屏正常降级。
- **N3（性能）**：动效仅用 `transform`/`opacity`（GPU 加速），骨架屏与光晕不阻塞渲染。
- **N4（可维护性）**：token 集中管理，组件复用，无魔法值、无内联样式堆砌。
- **N5（兼容）**：保留现有路由、API 调用、Pinia 状态与 DashPlayer 播放器核心逻辑不变。

## 不做的事

- 不做明暗双主题切换（本次仅深色）。
- 不改后端 API、不新增后端接口。
- 不实现依赖后端的新功能（真实推荐数据、点赞/收藏落库、关注/私信）——仅优化其前端占位与交互反馈。
- 不重构 `@vistack/ui` 独立组件库包（本次聚焦 web-client / web-admin 本地 `components/ui`）。
- 不改 DashPlayer 播放器核心逻辑（仅外围皮肤）。

## 验收标准

- **AC1（F2/F7/F8）**：web-client 与 web-admin 视觉统一为深色玻璃拟态，无浅色残留（含登录/注册/首页/管理端）。
- **AC2（F1/F9）**：全站颜色引用来自设计 token，无 `blue-*`/`pink-*`/`gray-*` 等硬编码颜色类名。
- **AC3（F3）**：导航链接全部指向真实路由，无死链；emoji 图标全部替换为统一图标。
- **AC4（F6）**：全站无原生 `alert`/`confirm`/`prompt`，统一用自定义 Toast + 对话框。
- **AC5（F4/F6）**：首页/列表具备骨架屏加载态与空态，表单具备明确错误态。
- **AC6（N5）**：改造后现有功能仍可用——上传/转码状态展示、DASH 播放、登录/注册、视频管理/删除。
- **AC7（N2）**：桌面与移动端（窄屏）布局正常，无溢出/错位。
