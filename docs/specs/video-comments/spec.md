# 视频评论系统 Spec

## 背景

当前 `video_comments` 表只有最简的邻接表字段（`video_id` / `user_id` / `parent_id` / `content`），模型实体已存在（`internal/model/entity/social/comment.go`），但没有对应的 API 路由、service 层和前端，评论功能实际上不可用。项目已具备可复用的基础设施：

- **社交计数**：`internal/interaction` 已有「点赞/收藏/播放量」的 Redis 计数 + Lua 原子脚本 + 异步 flush 落库 + 榜单模式。
- **内容安全**：`internal/danmaku` 已有 AC 自动机敏感词过滤器（并发安全的原子替换 root）。
- **文件管理**：`files` 表 + MinIO 已有「引用计数」生命周期管理，支持按 `ref_type` / `ref_id` 关联业务对象。
- **异步落库**：Kafka + worker 的成熟模式（弹幕落库、视频删除）。

本 spec 交付一套完整的视频评论系统，覆盖「发表评论 / 回复的回复（楼中楼）/ 文本与图片与表情包 / 敏感词与图片审核 / 点赞 / 计数 / 软删除」，后端 + 前端一起交付。

## 目标

- 提供视频评论的完整后端能力（发表、回复、列表、点赞、删除、计数、审核）与 web-client 前端界面。
- 复用现有 interaction 计数、AC 敏感词、files/MinIO 文件、Kafka worker 等基础设施，不重复造轮子。
- 解决「回复的回复」的级联表达：数据层保留树语义，展示层两级扁平。

## 功能需求

- **F1（发表一级评论）**：登录用户可对视频发表一级评论，内容包含纯文本（含 emoji）与可选的图片/表情包附件。发表后返回新评论 id。

- **F2（发表回复 / 楼中楼）**：用户可对任意评论或回复发表回复。数据层用 `root_id`（指向一级评论）+ `reply_to_id`（指向被精确回复的评论）表达级联关系；展示层只呈现两级：一级评论 + 其下扁平的回复列表，回复的回复通过「回复 @某人」的引用表达，不做深层缩进。

- **F3（评论列表与分页）**：按视频查询一级评论，时间倒序（id 倒序）游标分页；每个一级评论预取若干条最新回复用于列表摘要展示；可展开某条一级评论下的全部回复。

- **F4（内容类型）**：评论支持三种内容——纯文本/emoji、图片附件（每条评论最多 9 张）、图片表情包（GIF/PNG）。emoji 作为文本存储；图片与表情包作为附件引用 `files` 对象，按顺序渲染。

- **F5（文本敏感词拦截）**：发表评论/回复时，文本经 AC 自动机敏感词过滤，命中即拒绝发表。

- **F6（图片异步审核）**：含图片/表情包的评论先落库为「待审核」状态，由异步 worker 调用可插拔的图片内容安全审核器；审核通过转「可见」，违规转「隐藏」。未接入第三方供应商时使用「默认通过」的桩实现，保证链路可跑通。

- **F7（评论点赞）**：用户可对评论点赞/取消点赞，同一用户对同一评论幂等（重复操作不重复计数）；点赞数可读取展示。

- **F8（软删除）**：用户可删除自己的评论/回复；删除采用软删除，被删评论内容替换为「已删除」占位，保留楼中楼结构，其下的回复不被物理级联删除。

- **F9（计数冗余）**：评论的回复数、点赞数以及视频评论总数可读取；计数走 Redis 计数 + 异步落库，允许短暂最终一致。

- **F10（前端评论界面）**：web-client 提供评论列表（一级评论 + 楼中楼展开）、发表评论/回复（文本 + 图片 + 表情输入）、点赞、删除的完整交互。

## 非功能需求

- **N1（列表读取性能）**：一级评论列表走「索引 + 游标分页 + Redis 缓存」，避免全表扫描与 OFFSET 深分页；展开回复走 `root_id` 等值查询。
- **N2（计数最终一致）**：回复数/点赞数/评论总数的读写分离，Redis 计数优先、异步 flush 到库，异常时允许短暂不一致但最终收敛。
- **N3（文件生命周期）**：评论图片/表情包走 `files` 引用计数；发表评论时引用计数 +1，删除评论/审核拒绝时 -1，避免 MinIO 孤儿文件。
- **N4（审核状态机）**：评论状态在 `pending / visible / hidden / deleted` 之间流转，审核拒绝与软删除语义分离。
- **N5（兼容现有约定）**：沿用 Snowflake 主键、Gin 路由、GORM 模型与 AutoMigrate、zap 日志、`internal/xxx` 领域包分层。
- **N6（幂等与防重）**：点赞/取消点赞幂等；发表评论的写路径对重复提交做基本防护（幂等键或去重）。

## 不做的事

- 不做站内通知（被回复/被点赞提醒）。
- 不做热度排序 / 评论榜单（本轮只时间序，热度留后续）。
- 不做平台预置贴纸包管理（本轮仅 emoji + 用户上传图片表情包）。
- 不做无限层级嵌套展示（严格两级扁平 + 楼中楼）。
- 不做评论举报、置顶、精选、折叠等运营功能。
- 不做评论编辑（发表后不可修改，只可删除）。
- 不做 @ 提醒与私信。

## 验收标准

- **AC1（对应 F1）**：登录用户对视频发表一级评论成功，落库记录 `root_id` 为空，接口返回新评论 id。
- **AC2（对应 F2）**：对某条一级评论发表回复，落库记录 `root_id` 指向该一级评论、`reply_to_id` 指向被回复对象；对某条回复再回复，仍归属同一 `root_id`，前端以「回复 @xxx」引用呈现，无深层缩进。
- **AC3（对应 F3）**：列表按视频返回一级评论，时间倒序；传游标可翻页且无重复/遗漏；每个一级评论带若干条最新回复摘要；可展开拿到该一级评论下的全部回复。
- **AC4（对应 F4）**：纯文本/emoji、图片（≤9 张）、GIF/PNG 表情包均能发表并在前端按序正确展示；超过 9 张被拒绝。
- **AC5（对应 F5）**：文本包含敏感词时发表被拒绝，不产生评论记录。
- **AC6（对应 F6）**：含图片的评论落库为「待审核」，桩审核器将其转「可见」；模拟违规时转「隐藏」且前端不可见。
- **AC7（对应 F7）**：点赞后点赞数 +1，重复点赞不重复计数，取消后 -1，计数可正确读取。
- **AC8（对应 F8）**：删除评论后该评论内容显示「已删除」，其下的回复仍保留且可见；删除回复不影响同级其他回复。
- **AC9（对应 F9）**：评论的回复数、点赞数、视频评论总数在短暂延迟后收敛为真实值。
- **AC10（对应 F10）**：前端可完整走通「查看列表 → 发表评论 → 回复 → 上传图片/表情 → 点赞 → 删除」流程。
